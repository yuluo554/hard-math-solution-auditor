## 二、决策记录表

| 日期 | 决策 | 结论与理由 |
|---|---|---|
| 2026-10-15 | **命名约定：目录标签改用 `HWS-`** | 用户明确要求（原话"文件夹标签改为 HWS-"）。本批三题（`HWS-hard-math-solution-auditor` / `HWS-math-paper-replay-auditor` / `HWS-formal-math-navigator`）统一用 `HWS-` 取代日期标签；GitHub 仓库名仍用纯净名。**用户表态优先于系列旧惯例**（旧惯例见 [[project-series-panorama]] 的日期标签） |
| 2026-10-15 | **本批为"以 openPangu-2.0-Flash 为引擎"的题，引入新纪律「模型在环，但审计核心零模型可跑」** | 系列既有题是零模型依赖的确定性工具；本批以 LLM 为引擎。**92B MoE 本地自举硬件门槛高（Q4 约 50GB 权重）**，任何"免安装 exe 内自带模型"的承诺都会踩**交付物可达性预检**。故：模型接入 = 可插拔显式开关（OpenAI 兼容端点 / llama.cpp server / omni-infer），**不随包分发权重**；审计与判定核心 = 纯确定性、零模型依赖、可离线复跑；基准 = 预置模型输出快照 + 真值台账 |
| 2026-10-15 | **选题：难题解答步骤级审计（而非纯评测 harness）** | 弃"纯 LLM 数学评测 harness"：`math-evaluation-harness` 已 280★，开源不空白；且纯评测无确定性工具内核，**AI 时代独特性拷问不过关**（LLM 聊天可直接替代）。选定"步骤级审计+错误定位"因其过独特性拷问三关：①持久状态（步骤库/快照）②进入工作流的交付物（错误定位报告）③可复现测量基建（植入真值基准） |
| 2026-10-15 | **弃"解答生成/改写"与"自动评分"** | 生成/改写与审计定位冲突（工具应中立）；"总分"是可被误用的数字，且纯评测已不空白。**只交付定位不交付分数** |
| 2026-10-15 | **弃"数学 OCR / 公式识别"入首期** | 属 CV 域，非 openPangu-2.0-Flash 特长（其强项是文本推理与代码）；已有成熟工具。列扩展项 |
| 2026-10-15 | **弃"论文格式/文献著录审计"与"AIGC 痕迹检测"** | **与系列⑪文献审计工作台（`10-7-thesis-audit-workbench`）撞域**——系列纪律要求新题领域脱钩 |
| 2026-10-15 | **真值来源选"程序化植入"而非"公开题库"** | 公开题库许可需逐库核对（⬜），且题库真值是"答案对错"非"错误位置"——**错误位置真值只能靠植入获得**。故主力 = 合成竞赛级题+解答+植入已知错误步（错误位置与类型已知）；公开题库仅作可选回归集 |
| 2026-10-15 | **基准真值库只存输入与期望，观测运行时实算** | 若把观测冻进真值库，评测退化成"比对两个冻结字典"——**引擎坏掉也照样全绿**（假门）。观测须由 runner 把输入**真喂引擎**后实算 |
| 2026-10-15 | **首错锚定口径：多步同时 invalid 时报最小序号，并区分"独立失效/受污染"** | 只报"有错误"不给位置 = 未交付核心价值；报多个位置而无主锚 = 用户无从下手。故主锚唯一 + 传播关系显式 |
| 2026-10-15 | **`unverifiable` 与 `invalid` 必须分级** | 把"引擎验证不了"混入"确证错误"会**虚高判定**（系列纪律"判定语义不虚高"）。三级语义锁进测试 |
| 2026-10-15 | **独立重算路径与符号路径实现独立** | 两条路径若同源，会"同源错误互相印证"（看似交叉验证实则自证）。数值断言一律走独立重算 |
| 2026-10-15 | **误报率门槛 0 优先** | "干净解答被判为错"是最坏失败模式（会误导用户改对为错）。样本驱动层误报率须**实测**；无观测通道的层由 manifest **显式声明未测**（登记比沉默好） |
