# plan/03-基准套件设计

> 仓库 `HWS-hard-math-solution-auditor`（难题解答步骤级审计与错误定位器）。v1（2026-10-16）。

## 一、基准设计原则

### 1.1 真值来源 = 程序化植入

- 生成器知道错误在第几步、属哪一类
- 真值库只存 `input`（题+解答）与 `expect`（错误位置+类型+是否干净）
- **不存 `observed`**——观测由 runner 把输入真喂引擎后实算（防"比对两个冻结字典"的假门）

### 1.2 覆盖度双登记

- 按错误类型设最低覆盖项，写进 `data/rules/error_types.json`
- 新增错误类型无用例 → 生成器直接报错（堵死"悄悄做小分母"）
- 分母反射自代码常量，不手写

### 1.3 探活机制

- 基准必须含"坏实现被判未达标"的探活用例
- 注入故意错误的实现 → 基准必须报未达标

## 三、合成生成器设计

### 3.1 生成流程

```
题目模板库 → 程序化生成正确答案 → 生成解题步骤 → 植入已知错误步 → 产出真值记录
```

### 3.2 题目模板

首期 5 个竞赛级题目模板：

1. **二次方程求解**：`ax² + bx + c = 0`，已知 a,b,c
2. **数列求和**：等差/等比数列前 n 项和
3. **三角恒等式**：`sin²x + cos²x = 1` 类证明
4. **不等式证明**：均值不等式
5. **极限计算**：`lim(x→0) sin(x)/x = 1`

### 3.3 错误植入策略

| 错误类型 | 植入方式 |
|---|---|
| `illegal_algebra` | 在某步故意写 `a/b = a-b` |
| `divide_by_zero` | 在某步除以 0 或讨论缺失 |
| `dimension_mismatch` | 在某步混用不同量纲 |
| `induction_failure` | 基例缺失或归纳步错误 |
| `boundary_omission` | 漏讨论 x=0 等边界 |
| `symbol_typo` | 在某步写错变量名 |

## 四、指标计算

### 4.1 核心指标

| 指标 | 定义 | 门槛 |
|---|---|---|
| 错误定位准确率 | 首错序号命中率 | ≥90% |
| 误报率 | 干净解答被判为错 | **0 优先** |
| 答案一致性准确率 | 独立重算与模型答案一致判定准确率 | ≥95% |
| 覆盖度 | 按错误类型的覆盖项数/最低覆盖项数 | 100% |

### 4.2 指标计算代码

```python
def compute_metrics(results: list[BenchmarkResult]) -> Metrics:
    """
    计算基准指标。
    """
    total = len(results)
    clean_results = [r for r in results if r.ground_truth.is_clean]
    dirty_results = [r for r in results if not r.ground_truth.is_clean]

    # 误报率：干净解答被判为错
    false_positives = sum(1 for r in clean_results if r.first_error_step is not None)
    false_positive_rate = false_positives / len(clean_results) if clean_results else 0

    # 错误定位准确率
    correct_loc = sum(1 for r in dirty_results
                      if r.first_error_step == r.ground_truth.first_error_step)
    localization_accuracy = correct_loc / len(dirty_results) if dirty_results else 0

    return Metrics(
        false_positive_rate=false_positive_rate,
        localization_accuracy=localization_accuracy,
        total_cases=total,
        clean_cases=len(clean_results),
        dirty_cases=len(dirty_results)
    )
```

## 五、探活机制

### 5.1 坏实现探活

```python
def test_broken_implementation():
    """
    探活：故意用坏实现跑基准，必须报未达标。
    """
    broken_verifier = BrokenVerifier()  # 总是返回 ok
    results = benchmark_runner.run(broken_verifier)
    metrics = compute_metrics(results)

    # 坏实现必须暴露：误报率 > 0 或 定位准确率 < 100%
    assert metrics.false_positive_rate > 0 or metrics.localization_accuracy < 1.0
```

### 5.2 空分母分支

- 若某错误类型无用例，`not_enabled=true` + notes 声明 + exit 1
- "整套件数据缺失"的 not_enabled 与"跑了没过"同码不同义，文本可区分

## 六、覆盖度守门

### 6.1 生成器守门

```python
def check_coverage(generated_cases):
    """
    覆盖度守门：新增错误类型无用例 → 报错。
    """
    from data.rules.error_types import ERROR_TYPES  # 代码常量

    covered_types = {c.error_type for c in generated_cases if not c.is_clean}
    missing = set(ERROR_TYPES) - covered_types

    if missing:
        raise CoverageError(f"以下错误类型无用例: {missing}")
```

### 6.2 分母反射自代码常量

- 最低覆盖项数从 `data/rules/error_types.json` 读取
- 不手写数字，不硬编码

- 快照文件标 `.gitattributes -text` 防 EOL 改写字节
