# 模拟项目题：难题解答步骤级审计与错误定位器

> **性质**：自拟模拟项目题（**不参赛**，成果发布 GitHub 公开仓库）。交付形式为 **CLI + 桌面报告双形态**（PySide6 + PyInstaller exe，GitHub Release 附安装包），**审计核心离线即用、零模型依赖**；模型接入为可插拔显式开关。
> **目标产出**：GitHub 公开仓库（本地目录 `HWS-hard-math-solution-auditor`，`HWS-` 为本批命名标签；仓库纯净名 `hard-math-solution-auditor`）。
> **版本史**：

> - **v2（2026-10-18 修订）**—— 回访发现"承诺未兑现"，据实订正：
>   ① 报告导出（Markdown/JSON/HTML）由"文档写了"改为**真实现**（CLI `--report` + GUI 导出按钮 + 12 条测试）；
>   ② 首错编号对外统一 **1 基**（v0.1.0 报告里"步骤 2"与解释"第 3 步"自相矛盾）；
>   ③ 补齐 §三 实物：技术报告 `docs/技术报告.md`、演示 `docs/demo/demo.gif`；

> **定位宣言**：LLM 能解题，但**说不清自己哪一步错了**。本工具把解答（含 `<think>` 思维链）拆成可逐步复算的符号步骤，用确定性数学引擎判定每一步，交付**"错在第几步、错在哪、为什么错"**而不是一个笼统的分数，并可批量回归——LLM 聊天给不了持久状态、可复算证据与批量回归，本工具是 AI 数学时代的解答质检台。

## 一、项目介绍

**痛点**。以 openPangu-2.0-Flash 为代表的强推理模型在竞赛级数学上已达很高水平（官方模型卡：AIME 2026 93.3、HMMT Feb 2025 91.5、IMO-AnswerBench 76.5；**接上 Python 后 AIME 升至 98.1**）。但这类模型的输出有两个结构性问题：一是**正确率不等于可审计性**——最终答案对，中间步骤仍可能含非法变形（除以零、量纲不一致、归纳法失效、边界条件漏判）；二是**错误不可定位**——模型不会告诉你"哪一步开始坏"，人也难以逐行复核长证明。现有评测工具只给"总分"（对/错），不给"哪一步错"。

**为什么现在**。2026 年推理模型的思维链已可被程序化解析（openPangu-2.0-Flash 支持 thinking / non-thinking 双模式，思维链以 `<think>` 标签可解析），使"逐步审计思维链"在工程上第一次成立；而符号数学引擎（SymPy）足以对可符号化步骤做确定性判定。

**开源空白**（带检索式，基准日 2026-10-15）：

| 检索式（GitHub repo 检索） | total_count | 结论 |
|---|---|---|
| `llm math error localization` | **0** | 空白 |
| `math paper error detection` | **0** | 空白 |
| `aime benchmark harness` | **0** | 空白 |
| `llm self consistency math voting` | **0** | 空白 |
| `openpangu-2.0` | 4 | 2.0-Flash 相关仅 `mrexodia/llama.cpp-openPangu-2.0-Flash`(8★) 与 `bespokeontology/openPangu-2.0-Flash-CUDA-ROCm`(2★)，**全为推理引擎、零应用层** |

**软论据（辅助，不与硬论据并列）**：邻近件存在但均非闭环——`ZubinGou/math-evaluation-harness`(280★，纯评测 harness 无错误定位)、`aaronlyt/math-prm-openai-2023`(9★，过程奖励数据构造)、`LBurny/symkit-mcp`(12★，符号推导 MCP)、`kyal102/unitgate`(9★，量纲检查)、`marco…/scasella/Proofgrade`(0★，证明评分 API)。**"符号步骤级验证 + 错误定位 + 公开基准"的闭环不存在**。

## 二、任务要求

> **首期范围限定**：首期实装 5 个模块（①–⑤），其余列扩展项（§六）。所有模块共用同一套工程底座：**步骤模型 + 判定三级语义 + 证据链 + 合成真值基准**。

### 1）解答摄入与步骤切分

- **输入**：模型输出（含 `<think>` 思维链）或 LaTeX/纯文本解答，或**预置输出快照**（见模块⑤）。
- **输出**：结构化**步骤序列**（每步 = 序号 + 原文片段 + 归一化表达式候选 + 来源行号）。
- **引擎**：确定性解析器（零模型）；模型仅在"解析兜底"开关开启时参与（默认关）。
- **确定性纪律**：**不可符号化的步骤一律标 `unsymbolizable`，不得虚高判定为 ok**；切分覆盖率必须**如实报告**（分母 = 检出步骤数，分子 = 成功归一化数），不得只报分子。

### 2）步骤级符号验证

- **输入**：模块①的步骤序列。
- **输出**：每步 verdict = `ok` / `invalid` / `unverifiable`（三级语义），`invalid` 必须附**最小反例**（如代入后不等的具体取值）。
- **引擎**：SymPy 逐步验证相邻步的等价性与合法性——方程变形、代入、因式分解、约分、取极限、求和、积分、不等式方向。
- **确定性纪律**：**"验证不通过"与"验证不了"必须区分**（`invalid` vs `unverifiable`）；引擎对某类变形无能力时标 `unverifiable` 并登记能力覆盖度，**不得默认判 ok**；判定必须可复跑（同输入同结论）。

### 3）错误定位与首错锚定

- **输入**：模块②的逐步 verdict。
- **输出**：**首个失效步**（主锚）+ 后续步骤标"受污染"（downstream-contaminated）+ 局部最小反例。
- **引擎**：确定性传播逻辑（非启发式猜测）。
- **确定性纪律**：首错锚定必须**唯一**且可解释——当多个步骤同时 `invalid` 时，报告**最小序号**为首错并显式说明其余为"独立失效"或"受污染"；**不得只报"有错误"而不给位置**。

### 4）独立重算与答案一致性交叉验证

- **输入**：解答的最终断言 + 模块①归一化结果。
- **输出**：三态判定——独立重算与模型最终答案 **一致 / 不一致 / 无法独立重算**。
- **引擎**：独立数值重算路径（与符号路径**实现独立**，防"同源错误互相印证"）。
- **确定性纪律**：容差与数值口径**一处定义**（落 `plan/02` 的唯一定义点），注记文本与算法同源；数值类断言一律走独立重算，不采信符号路径的自证。

### 5）内置评测基准（旗舰，零模型依赖可离线复跑）

- **输入**：合成竞赛级题+解答生成器产出的**带植入错误**的解答集 + **预置模型输出快照**。
- **输出**：指标表——**错误定位准确率**（首错序号命中率）、**误报率**（干净解答被判为错 = 误报，**门槛 0 优先**）、按错误类型登记覆盖度、答案一致性判定准确率。
- **引擎**：基准 runner（零模型）。
- **确定性纪律**：
  - **真值来源 = 程序化植入**（生成器知道错误在第几步、属哪一类），**真值库只存输入与期望，观测在运行时实喂引擎实算**（防"比对两个冻结字典"的假门）；
  - **预置模型输出快照**使指标不依赖当场跑模型：快照含模型名、版本、生成参数、原始输出与 sha256，**随仓只存快照与真值台账，不分发模型权重**；
  - 覆盖度口径：按错误类型（非法代数变形 / 除以零 / 量纲不一致 / 归纳法失效 / 边界条件漏判 / 符号错抄）各设**最低覆盖项**，写进 manifest；**新增错误类型而无用例 → 生成器直接报错**，堵死"悄悄做小分母"。
- **本模块是含金量核心**：它把"模型很强"这个背景变成**可复现的审计能力指标**，且**离线可跑、零 API 依赖**。

## 六、边界与非目标

- **不做**：解答生成与改写（本工具只审计，不产出新解答）；查重；自动评分排序（不输出"总分"这种可被误用的数字）；数学 OCR（图像公式识别属扩展项，非首期）。
- **确定性纪律（口径）**：所有判定必须可离线复跑且同输入同结论；**模型接入是可插拔显式开关（OpenAI 兼容端点 / llama.cpp server / omni-infer），默认关闭，不随包分发模型权重**；审计核心（解析/验证/定位/基准）为纯确定性、零模型依赖；预置快照使指标不依赖当场跑模型。
- **判定边界**：`unverifiable`（引擎能力外）与 `invalid`（确证错误）**必须区分**，报告不得把"验证不了"说成"错"或"对"；自然语言步骤 → 符号表达式的解析存在覆盖度上限，报告须显式列出**未覆盖步骤数与原因**。
- **免责红线**：审计结论为**提示**，不构成学术结论或对模型/作者的评判；`unverifiable` 不等于错误。
- **隐私红线**：全本地存储、零上传；模型开关开启时仅发送用户选中的解答文本，设置页明示。
- **品牌隔离**：不复制姊妹项目代码；文档不提及其余项目的业务领域。
